# 2026-10-12 微信首次登录修复

线上用户表残留 username varchar(50) NOT NULL 且没有默认值。当前 User 模型不再写入这个旧字段，微信用户创建返回 MySQL 1364。

最小迁移：20261012_allow_legacy_username_null.sql，只将 username 改为允许 NULL，保留原类型、字符集、排序规则及所有索引。不删除字段，不改已有值，不同步业务数据，不需重新构建或重启后端。

验收：
| 场景 | 预期 |
| --- | --- |
| 旧约束下微信用户创建 | 1364，复现线上问题 |
| 执行迁移后两个新用户创建和更新 | 成功，username/phone 为 NULL |
| 历史 username | 原值不变 |
| 重复 OpenID | 仍被唯一约束拒绝 |
| 用户/管理员及家庭越权回归 | 原有测试通过 |

本地回归使用临时表复制 users 结构，并加载实际迁移 SQL；不修改实际 users 表。运行 SPORT_INTEGRATION_CONFIG 指向本地私密配置，执行 go test ./... 和 go vet ./...。禁止对线上数据库运行测试。

线上执行必须先获得本次表结构变更的用户确认。执行前重新核对 username 类型、非空约束、字符集和索引，并创建最新私有备份。执行后确认字段允许 NULL、其余字段与索引及原有数据不变；最后由用户重试真实微信登录。已准备的首次备份：/root/sport-login-repair-20261012/users-before.sql.gz。

回滚限制：只有 username IS NULL 的记录数为 0 时，才可以恢复 NOT NULL。新用户成功创建后，不得为恢复旧约束而删除或伪造用户数据；保留兼容字段并另行评估恢复方案。不要直接恢复整个数据库覆盖其他用户的新数据。
