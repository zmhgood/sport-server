# 管理后台锻炼参与统计

范围：扩展现有管理员 dashboard API 和管理后台，不修改小程序，不新增数据库结构，不部署。

## 时间与统计口径

所有日期以北京时间（Asia/Shanghai）计算。页面最近7天/30天包含今天；不同指标的实际日期单独返回并显示。

| 指标 | 分子 / 计数 | 分母 / 时间窗口 |
| --- | --- | --- |
| 首次完成率 | 注册当天起7个自然日内，至少完整完成一个计划动作的用户数 | 观察期已经结束的注册用户；注册日期窗口为主窗口整体向前移7天。无家庭、无计划、无进度用户也在分母中 |
| 每周锻炼天数 | 每人每周有效锻炼日期去重，分为1–2、3–4、5–7天 | 仅有锻炼的用户；至少完成一组算锻炼日。按周一至周日，7天视图展示最近1个完整周，30天展示最近4个完整周 |
| 周锻炼留存 | 前一周锻炼用户在后一周再次锻炼的人数 | 前一周锻炼用户。后一周对应上表各完整周，不含本周；返回两周具体日期 |
| 活跃家庭 | 每日至少有一名成员完成一组的家庭数，以及期间去重家庭数 | 使用主窗口7天/30天。期间总数不是每日数量之和 |

首次完成观察期是注册日到注册日+6（含两端），不是168小时。比如10月22日查询最近7天，注册批次是10月9日至15日，最晚一批观察到10月21日结束。

零分母返回 `rate: null`，页面显示“无样本”；有样本无人完成返回0。比例使用0..1的小数，页面同时显示分子与分母。历史被注销/软删除的注册用户仍保留在历史注册批次中，可能与“当前注册用户”卡片口径不同。

统一使用 `goal_completions` 的最新有效逻辑进度：同用户、同计划、同动作、同业务日期取最大未删除记录ID，然后验证动作关联和组数。撤回为0不算活跃，异常组数不恢复旧进度；重复提交不累计。完整完成需组数等于对应历史版本的目标组数。

跨家庭/计划同日仅计一个用户锻炼日；同用户在两个家庭分别锻炼可以使两个家庭活跃。退出或被移除成员、归档计划/动作/家庭的历史贡献保留。不叠加镜像流水或派生日汇总。四项指标和原有图表在同一个只读 repeatable-read 事务中读取。

## API 增量

`GET /api/admin/stats/dashboard?days=7|30` 保留原字段，新增 `engagement`：

- `activation`: `startDate`, `endDate`, `eligibleUsers`, `completedUsers`, `rate`。
- `weeklyExerciseDays[]`: `startDate`, `endDate`, `activeUsers`, `oneToTwoDays`, `threeToFourDays`, `fiveToSevenDays`。
- `weeklyRetention[]`: 前一周 `startDate/endDate`，后一周 `returnStartDate/returnEndDate`，`cohortUsers`, `returnedUsers`, `rate`。
- `families`: `activeCount`, `daily[{date,familyCount}]`。

前端拒绝缺字段、错误周锚点、人数/分母矛盾和不一致比例。请求失败保留上次完整数据及对应时间选项，不显示伪造的0。首次加载失败显示重试入口。

## 验收矩阵

| 风险 | 验证方式 |
| --- | --- |
| 尚未成熟注册批次、注册无计划用户遗漏、完成日混入注册窗 | MySQL注册边界夹具 + 固定人数断言 + 原始行独立对账 |
| 跨计划/家庭重复、重复提交、撤回、非法组数、镜像重复 | 真实MySQL逻辑进度夹具；所有4指标与独立Go聚合比较 |
| 跨年、闰年、上海午夜、周日尚未结束 | 时间单测及数据库周边界测试 |
| 历史成员/家庭/动作软删除、动作版本变化 | 使用对应历史目标组数，确认历史贡献保持 |
| 无数据、零分母、日期缺失、空数组 | API/集成测试、前端语义校验与浏览器空状态 |
| 数据泄露、异常参数、数据库错误 | 既有管理员权限/参数/故障回归 |
| 7/30切换、加载失败、窄屏 | 管理后台构建、Node测试、1440/768/390px浏览器验证 |

数据库测试须提供 `SPORT_INTEGRATION_CONFIG`，配置只允许localhost和`sport_qa_`库。未提供配置而skip不能视为通过。独立对账直接读取基础表、在Go中选最新记录再聚合，不调用生产统计查询或聚合函数。

本次统计反映用户自行记录的锻炼，不等同设备测量、登录访问或医学效果；不提供历史应练任务完成率（目前没有完整应练任务快照）。

## 本地验收结果（2026-10-22）

- 独立本机 MySQL：`go test -count=1 -race -json ./...` 通过57个顶层测试、176项含子测试断言用例，失败0、测试跳过0；没有测试文件的包不计入测试数量。`go vet ./...` 和后端构建通过。
- 新增4个数据库测试：综合原始行对账（7/30天）、空样本、跨年完整周、自然日注册边界与上海午夜。管理员HTTP测试同时核对新增响应结构。对账样本首次完成率7天2/4、30天6/10，末个完整周留存5/8，期间去重家庭2个；均为合成数据。
- 管理后台34项Node测试及生产构建通过。构建仍有原有Sass旧API和大chunk提示。
- Chrome本地页面9项统计流程检查及8项既有后台回归检查通过；1440、768、390px截图复核，包含缩窄窗口后侧栏自动折叠、图表滚动查看、7/30天切换、首次加载失败、失败保留旧数据、重试、缺字段和无样本状态。
- 浏览器主统计响应来自真实MySQL测试夹具导出；故障与空数据通过仅监听本机的测试API注入，并非生产数据。环境缺少Browser插件，采用已安装Playwright和系统Chrome；自动等待在本机出现停滞，改用短间隔DOM读取及非导航按钮点击后显式检查状态。预期503故障和开发favicon缺失不计为应用运行异常。
- 已清理本次独立数据库。未进行生产数据核对或线上压测，未部署、未修改小程序、未提交审核。
